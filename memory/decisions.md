# Decisions

이 파일은 장기적으로 유지할 프로젝트 운영 결정을 기록합니다.

## 2026-05-17

- 루트에는 `README.md`, `AGENTS.md`, `DESIGN.md`, `memory/`, `tools/`를 GitHub 공유 대상으로 둡니다.
- 날짜형 작업 폴더(`YYYYMMDD_작업제목/`)는 로컬 작업공간으로 두되 기본적으로 GitHub에 올리지 않습니다.
- 루트 `README.md`는 GitHub 저장소 방문자가 clone, 의존성 설치, Codex Desktop 플러그인 추가, Remotion/HyperFrames 실행 흐름을 따라가기 위한 온보딩 문서로 유지합니다.
- `DESIGN.md`는 특정 작업 폴더가 아니라 루트에 두고 모든 영상 프로젝트에서 공통으로 참고합니다.
- 새 작업은 `YYYYMMDD_작업제목` 폴더를 만든 뒤 그 안에서 진행하며, 새 작업이 기존 날짜형 작업 폴더를 참조한다고 가정하지 않습니다.
- `memory/`는 자동 저장 기능이 아니라 에이전트가 직접 읽고 업데이트하는 프로젝트 레벨 반자동 메모리로 운영합니다.
- 스크립트 기반 모션그래픽 공통 레이아웃은 상단 설명 카드, 중앙 인포그래픽, 하단 자막 안전영역과 별도 라벨 영역처럼 안전 영역을 분리하는 방식을 우선합니다.
- 장면별 라벨을 아이콘, 연결선, 카드, 차트 위에 절대좌표로 얹지 않습니다.
- 작업 폴더 루트 `README.md`는 더 이상 만들거나 참조하지 않습니다. 작업 기록이 필요하면 에이전트 응답과 관련 산출물 경로로 충분히 남깁니다.
- 음성 원본 파일은 HyperFrames와 Remotion의 공통 소스이므로 작업 폴더의 `audio/` 안에서 관리합니다. 사용자가 첨부 파일명을 미리 맞출 필요는 없습니다.

## 2026-05-24

- 영상 제작 요청에는 음성 파일과 스크립트 파일을 함께 첨부하는 것을 기본으로 합니다. 첨부 파일명은 자유롭게 두고, Codex가 작업 폴더의 `audio/`와 `script/` 안에 기준 파일로 정리합니다.
- 첨부자료의 브랜드, 톤, 색상, 스타일 단서가 루트 `DESIGN.md`와 겹치면 사용자 명시 요청을 최우선으로 두고, `DESIGN.md`는 공통 제작 원칙, 첨부자료는 작업별 브랜드 보정값으로 다룹니다. 명확한 충돌은 사용자 확인 또는 작업별 디자인 브리프로 기록합니다.

## 2026-05-25

- 새 영상 제작 요청을 받으면 디자인 기준 확인 단계에서 `https://github.com/VoltAgent/awesome-design-md`의 `DESIGN.md` 종류를 리스트업해 사용자에게 선택지를 제시합니다. 선택된 외부 `DESIGN.md`는 작업별 스타일 레퍼런스로만 사용하고, 사용자가 루트 기본값을 승인하면 루트 `DESIGN.md` 규칙을 그대로 사용합니다.
- 승인된 장면 타임라인은 작업 폴더의 `timeline/scenes.json`에 저장하고 Remotion, HyperFrames, QA의 공통 기준으로 사용합니다. 최종 검수에는 장면 경계 전후 프레임, 텍스트 잘림/안전 여백/명암 대비, 최종 MP4 길이, 오디오 시작 오프셋, 디버그 UI 잔존 여부 확인을 포함합니다.
- 사용자가 영상 제작 도구를 지정하지 않으면 Orchestrator가 첨부 스크립트, PDF/문서/URL, 영상 목적을 보고 도구를 추천합니다. 숫자, 데이터, 차트, 반복 템플릿 중심은 Remotion을 우선하고, 브랜드 소개, 타이포그래피, 웹 기반 감각적 모션 중심은 HyperFrames를 우선합니다.
- 새 영상 제작 요청에서 도구나 디자인 기준이 빠져 있으면 작업 폴더 생성과 구현 전에 도구 추천 승인, `awesome-design-md` 선택 또는 루트 `DESIGN.md` 기본값 승인을 먼저 받습니다. "바로 진행" 같은 포괄 지시만으로는 이 확인을 생략하지 않습니다.
- PDF, 문서, 기획안, URL만 제공된 영상 요청은 핵심 메시지, 대본 초안, 장면 구성, 인포그래픽 방향, 무음 또는 임시 타이밍 영상 초안까지 진행할 수 있습니다. 다만 먼저 최종 싱크 영상이 아니라는 점을 설명합니다. 이후 제공된 음성 파일 및 원본 스크립트가 초안의 대본, 장면 구성, 톤과 잘 맞으면 타임라인 재조정과 재렌더로 진행하고, 메시지, 순서, 분량, 톤이 다르면 장면 구성과 디자인 방향을 재검토하거나 전면 재제작할 수 있음을 설명합니다. PDF/URL과 음성 파일 및 원본 스크립트가 함께 제공되면 음성 파일은 싱크 기준, 원본 스크립트는 내레이션 기준, PDF/URL은 내용 보강과 스타일 참고 기준으로 사용합니다.
- 큰 제목과 핵심 문구는 자동 줄바꿈에만 맡기지 않고 의미 단위 줄 배열로 관리합니다. 한국어 제목에서 한 글자, 조사, 어미, 짧은 술어 어절만 다음 줄에 고립되면 레이아웃 오류로 보고 수정합니다.

## 2026-05-18

- 프로젝트 루트 폴더명은 `AI Video Studio`입니다. 문서와 예시 경로에서도 이 이름을 기준으로 사용합니다.
- 영상 생성 작업을 병렬화할 때는 Orchestrator가 전체 판단권과 최종 책임을 갖고, Intake/Sync, Design, QA, Render/Packaging Agent를 기본 구성으로 둡니다. Remotion Agent와 HyperFrames Agent는 사용자 요청 또는 Orchestrator 선택에 따라 조건부로 실행합니다.
- 공통 에이전트 프로필 폴더는 루트에 만들지 않고, 작업별 실행 지시가 필요할 때만 날짜형 작업 폴더 안의 `agent-briefs/`에 역할별 brief를 둡니다.

## 2026-06-07

- 모션그래픽은 인포그래픽 중심 레퍼런스처럼 인포그래픽을 중심으로 설계하고, 화면 하단 18-22%는 자막 안전영역으로 먼저 비워둡니다. 핵심 인포그래픽, 라벨, 장식, 진행 막대는 이 영역에 배치하지 않습니다.
- 장면 라벨은 하단 자막 영역 대신 인포그래픽 내부, 상단 설명 아래, 또는 측면 트레이에 배치합니다.

## 2026-08-16

- 제작 도구 선택지에 White Animation을 추가한다. 이 모드는 `geeklee/srt-whiteboard-animation`(MIT)을 작업별 `source-whiteboard/`에서 사용하며, 원본 스크립트와 `.wav` 음성 파일이 모두 첨부된 경우에만 제시한다.
- White Animation의 싱크 기준은 로컬 전사 결과 `transcript/sentences.json`과 같은 실행에서 생성한 `transcript/subtitles.srt`다. 추정 타임라인 SRT는 최종 렌더에 사용하지 않는다.
- White Animation의 펜은 원본 레포 파일을 보존한 상태에서 작업별 정리 사본을 사용한다. 펜과 손의 외형·투명 배경은 유지하고 펜대의 중국어만 제거한다.
- White Animation은 `srt-whiteboard-animation`의 자체 스타일 가이드를 시각 기준으로 사용한다. 외부 `DESIGN.md` 선택이나 사용자 디자인 승인은 요구하지 않으며, 루트 `DESIGN.md`는 여백·가독성·싱크·검수 안전 규칙에만 적용한다.
- 사용자가 텍스트 제외를 명시하지 않는 한 White Animation 최종본에는 장면별 제목 1개와 핵심어 2–4개의 별도 텍스트 오버레이를 기본 포함한다. 원화는 무문자로 유지하고, `timeline/overlays.json`의 실제 발화 `startMs`에 맞춰 `assets/fonts/gaegu-bold.ttf`로 렌더한다. 1920×1080에서는 왼쪽 620px 텍스트 열과 오른쪽 화이트보드 영역을 최소 48px 이상 분리하며, 하단 자막 안전영역을 비운다.
- Remotion과 HyperFrames의 선택 효과 라이브러리로 Anime.js와 Motion을 작업별 프로젝트 의존성으로 사용한다. 같은 속성은 Anime.js·Motion·GSAP·CSS 중 하나의 엔진만 제어하며, Remotion 최종본은 프레임 기반 타임라인과 still render로 재현성을 검수한다.
- 사용자가 중간 검수나 승인을 명시적으로 요청하지 않으면 영상 제작의 사용자 대상 검수 게이트, 검수 자료 제시, 단계별 컨펌 요청은 제외하고 최종 산출물까지 진행한다. 다만 싱크·안전영역·오디오·출력 무결성 같은 내부 QA는 유지하며, 치명적 오류나 사용자 선택이 꼭 필요한 경우에만 중단해 확인한다.
